# writer PRD (초안)

> 상태: 초안 · 작성일 2026-10-30

## 1. 개요

writer는 devlog(Astro 블로그) 글의 초안 작성, 검토, 수정을 돕는 MCP 서버다. MCP 서버로 동작하고, Claude Code에서 도구로 호출한다. 블로그 빌드나 배포와는 무관한 로컬 전용 툴이다. devlog 레포에는 `tools/writer` 서브모듈로 붙어 있다.

## 2. 목표

1. **정밀도**: 스킬을 한 번 호출해서 끝내지 않는다. 검토와 수정을 여러 회차로 돌리되 회차마다 작성자가 수정안을 확인해서 devlog 작성 규칙을 더 정확하게 지킨다.
2. **MCP 개발 포트폴리오**: MCP 서버를 설계하고 구현한 사례로 쓴다. 도구 정의, 입출력 스키마, 에러 처리까지 포함한다.
3. **LLM 툴 개발 포트폴리오**: Anthropic SDK 기반의 에이전트 루프, tool use, 구조화 출력을 직접 구현한 사례로 쓴다.
4. **독립성**: writer와 사이트 설정 파일(`writer.templates.json`, `writer.guide.md`)만으로 초안, 검사, 검토, 수정이 같은 수준으로 돌아간다. 사이트의 하네스(스킬, `CLAUDE.md` 같은 에이전트 지시 문서)를 읽지 않고, 그것이 없어도 동작이 달라지지 않는다.
   - 작업 순서는 MCP 서버 instructions로 호출한 쪽에 알린다.
   - 어느 블로그에나 맞는 글쓰기 원칙은 writer 코드(`writing/`)에 둔다.
   - 사이트마다 다른 기준만 사이트 안내 문서에서 읽는다. 두 설정 파일은 없어도 서버가 시작하고 내장 기본값으로 돈다.

### 비목표

- 블로그 사이트 기능(페이지, 컴포넌트, 배포)은 다루지 않는다.
- 여러 사용자가 쓰는 서비스나 호스팅은 만들지 않는다.
- 글을 공개하는 작업(`draft: false` 전환, `post-index.md` 행 추가)을 자동으로 하지 않는다. 사용자가 확인한 뒤에만 한다.

## 3. 핵심 요구사항: LLM Provider 교체

API 비용 없이 실사용하면서, 구현은 API 기준으로 제대로 갖춘다.

| Provider | 호출 방식 | 과금 | 용도 |
|---|---|---|---|
| `anthropic-api` | Anthropic SDK + API 키 | API 토큰 과금 | 정식 구현. 포트폴리오 시연, 남이 쓰는 경우 |
| `claude-code` | `claude -p` 헤드리스 호출 | Claude 구독 | 본인 실사용 |

- 서버 안에서 LLM을 부르는 곳은 검토(`review_post`)와 수정 제안(`revise_post`)뿐이다. 글을 쓴 쪽과 다른 새 맥락에서 같은 기준으로 보기 위해서다. 조사와 초안 작성은 호출한 쪽(Claude Code)이 맡는다. 호출한 쪽은 웹 검색과 대화 맥락을 쓸 수 있고, 서버 안의 LLM은 도구 없이 돈다.
- 설정값 하나(예: `LLM_PROVIDER`)로 바꿔 끼운다.
- Provider 인터페이스는 "메시지와 출력 스키마를 받으면 텍스트나 JSON을 돌려주는" 수준으로 좁게 정의한다. 루프 제어, 도구 실행, 규칙 검사는 writer 코어가 맡는다. 어느 Provider를 쓰든 동작이 같아야 한다.
- API Provider는 tool use, 구조화 출력, 프롬프트 캐싱 등 SDK 기능을 제대로 활용한다. claude-code Provider는 같은 인터페이스에 맞추는 어댑터다.

## 4. 아키텍처

```
Claude Code ──MCP(stdio)──▶ writer
                             ├─ mcp/      MCP 서버, 도구 정의
                             ├─ loop/     작성·검토 루프 오케스트레이션
                             ├─ rules/    결정적 규칙 검사 (LLM 미사용)
                             ├─ content/  글 찾기, frontmatter와 본문 파싱
                             ├─ templates/ 사이트 템플릿 파일 읽기
                             ├─ writing/  내장 글쓰기 원칙, 사이트 안내 문서 읽기
                             └─ llm/      Provider 인터페이스
                                  ├─ anthropic-api
                                  └─ claude-code
```

- **언어**: TypeScript (Node). MCP SDK와 Anthropic SDK 둘 다 공식 지원한다.
- **사이트 경로**: 상대경로를 하드코딩하지 않고 설정(`SITE_ROOT`)으로 받는다. writer 레포만 따로 clone해도 쓸 수 있게 하기 위해서다.

## 5. MCP 도구 (초안)

| 도구 | LLM 사용 | 설명 |
|---|---|---|
| `check_post` | X | 글 하나에 규칙 검사를 돌리고 위반 목록을 돌려준다 |
| `list_posts` | X | 글 폴더의 모든 글을 frontmatter와 함께 돌려준다. 이미 다룬 소재와 링크할 글을 찾는 데 쓴다 |
| `get_template` | X | 초안용 템플릿을 돌려준다. 절마다 조사해서 채울 것과 작성자에게 남길 것, 초안 작성 지침이 들어 있다 |
| `review_post` | O | 규칙 검사와 LLM 비평을 합쳐 검토 의견을 낸다. 파일은 고치지 않는다 |
| `revise_post` | O | 규칙 error, 작성자가 고른 지적, 피드백을 반영한 수정 목록을 돌려준다. 한 번 호출이 한 회차다. 파일은 고치지 않는다 |

LLM을 쓰지 않는 도구부터 구현해서 MCP 연결을 먼저 검증한다.

## 6. 템플릿 (templates/)

템플릿은 사이트 레포의 JSON 파일(`WRITER_TEMPLATES`, 기본값 `writer.templates.json`)에 둔다. 절 이름, 참고 자료 제목처럼 사이트마다 다른 값이기 때문이다. 서버는 시작할 때 파일을 한 번 읽고, 없거나 형식이 틀리면 시작하지 않는다. 모든 도구의 `template` 입력 값이 이 파일에서 나온다.

템플릿은 이런 글에 보통 들어가는 내용을 적은 가이드라인이다. 절 이름을 바꾸거나 빼도 위반이 아니고, 절을 검사하는 규칙도 없다.

| 항목 | 쓰는 곳 | 설명 |
|---|---|---|
| `referencesHeading` | 규칙 검사 | 각주 설명 줄을 모으는 마지막 절의 제목 |
| `sections` | 초안 | 절 제목과, 절마다 `research`(공개 자료를 조사해 각주와 함께 채울 것)와 `prompt`(작성자가 직접 쓸 것) |
| `frontmatter` | 초안 | frontmatter 필드별 `research`와 `prompt` |
| `criteria` | 검토 | LLM 비평에 더할 기준. 글을 고치면서 필요해지면 넣는다 |

초안은 `prompt` 내용을 지어내지 않는다. 작성자가 대화에서 알려 준 것만 쓰고, 나머지는 본문에 `<!-- TODO: ... -->` HTML 주석, frontmatter에 `# TODO:` YAML 주석으로 남겨 작성자가 채운다. 둘 다 사이트에는 보이지 않으므로, 공개된 글에 남은 TODO는 규칙 검사가 알려 준다.

devlog 템플릿은 `article`(기승전결로 쓰는 일반 글), `game-review`(게임 후기, 데브로그 글과 연결), `escape-review`(방탈출 후기), `culture-review`(공연·드라마·영화 감상) 네 가지다.

## 7. 규칙 검사 (rules/)

각주 규칙과 사이트가 내는 JSON Schema로 글을 코드로 검사한다. 위반 결과는 다음 루프의 피드백으로 넣는다.

- **frontmatter**: 사이트의 JSON Schema에 맞는지 본다. 스키마에 없는 필드와 없는 `thumbnail` 파일도 잡는다.
- **각주 짝**: 본문의 표시와 설명 줄이 서로 맞는지, 같은 설명 줄이 중복되지 않았는지 본다.
- **각주 링크**: 설명 줄에 http(s) 링크가 있는지 본다. 설명 문장은 없어도 된다.
- **각주 위치**: 설명 줄이 템플릿의 참고 자료 절 안에 있고, 그 절이 글의 끝인지 본다. 제목 깊이는 보지 않는다.
- **각주 설명 길이**: 150자를 넘으면 경고한다.
- **TODO**: 공개된 글(`draft`가 `true`가 아닌 글)에 TODO 주석이 남아 있으면 참고(info)로 알린다.

LLM 비평은 코드로 판정할 수 없는 항목만 맡는다. 예를 들면 사실 주장에 근거가 있는지, 문장이 명료한지, 수정 흔적("X가 아니라 Y")이 남았는지, 줄임말이 전체 이름보다 먼저 나오는지 같은 것이다. 기준은 writer에 내장된 글쓰기 원칙에 사이트 안내 문서(`WRITER_GUIDE`, 기본값 `writer.guide.md`)와 템플릿별 기준(`criteria`)을 더한 것이다. 같은 원칙과 안내 문서를 `get_template`이 초안 작성 쪽에, `revise_post`가 수정 쪽에 넘긴다.

## 8. 루프 설계

작성자가 회차마다 수정안을 보고 다음 회차를 정하는 루프다. `revise_post` 한 번이 한 회차이고, LLM을 한 번 호출한다.

1. `review_post`: 규칙 검사와 LLM 비평 결과를 작성자에게 보여 준다
2. 작성자가 반영할 지적을 고른다
3. `revise_post` 입력: 글 경로, 고른 지적, 작성자 피드백
4. 수정 (LLM): 규칙 error, 고른 지적, 피드백을 반영한 수정 목록(`quote`, `replacement`)을 만든다
5. 규칙 검사 (코드): 수정 목록을 적용한 글을 다시 검사한다
6. 출력: 적용한 수정, 적용하지 못한 수정, 수정 후 남은 규칙 위반
7. 작성자가 수정을 승인하면 호출한 쪽(Claude Code)이 파일에 적용한다. 남은 문제가 있으면 피드백과 함께 3으로 돌아간다

- writer 서버는 글 파일을 쓰지 않는다. 다음 회차는 수정이 적용된 파일을 읽으므로 서버가 회차 사이의 상태를 들고 있지 않는다. 회차별 기록은 git diff와 대화에 남는다.
- 비평 지적은 작성자가 고른 것만 고친다. 글만 봐서는 임의로 만든 예시 코드나 일부러 쓴 표현을 구분하기 어렵기 때문이다. 실제 글의 비평 `error` 6건이 모두 작성자 확인에서 문제가 아니었다.
- 규칙 warning은 고치라고 넘기지 않고 결과로 돌려준다.
- 고칠 것(규칙 error, 고른 지적, 피드백)이 없으면 LLM을 호출하지 않는다.
- LLM이 낸 `quote`가 글에 없거나 여러 번 나오면 그 수정은 적용하지 않고 결과에 따로 담는다.

## 9. 안전·운영

- writer 서버는 글 파일을 쓰지 않는다. 초안은 호출한 쪽이 `draft: true`로 새 파일에 저장하고, 기존 글을 덮어쓰지 않는다. `get_template`의 지침에 이 내용이 들어 있다.
- API 키는 환경변수로만 받고 레포에 커밋하지 않는다.
- **[확인 필요]** 구독(claude.ai 로그인)으로 돌리는 방식은 본인이 개인 툴에서 쓰는 용도로 한정되는 것으로 알고 있다. Agent SDK 기반 제품을 남에게 배포하면서 claude.ai 로그인을 쓰게 하는 것은 Anthropic이 허용하지 않는 것으로 기억한다. 구현 전에 현재 약관과 문서로 확인하고, README에 "남이 쓸 때는 `anthropic-api` Provider 사용"을 명시한다.
- `claude-code` Provider는 `claude -p`에 `--output-format json`과 `--json-schema`를 넘겨 스키마를 강제하고, `--tools ""`와 `--strict-mcp-config`로 도구와 MCP 서버를 끈다.

## 10. 마일스톤

1. **M1 뼈대**: TS 프로젝트, MCP 서버, `check_post` (LLM 없음), 템플릿 선택 구조. Claude Code에서 호출되는지 확인한다.
2. **M2 Provider**: 인터페이스, `anthropic-api` 구현, `claude-code` 어댑터.
3. **M3 루프**: `review_post`, `revise_post`. 회차마다 작성자가 확인하는 수정 루프.
4. **M4 초안**: `list_posts`, 사이트 템플릿 파일, `get_template`. 호출한 쪽이 템플릿을 받아 조사하고 초안을 쓴 뒤 `check_post`로 검사한다.
5. **M5 포트폴리오**: README, 아키텍처 설명, 시연 기록.
